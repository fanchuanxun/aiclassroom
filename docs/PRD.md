# PRD — AIClassRoom

> 产品需求文档。来源：《教学讲义-从零搭建 AI 智能体互动课堂》。

最近更新：2026-09-09

---

## 1. 产品愿景

把「被动看文档/视频」升级为「沉浸式多智能体课堂」。

**解决的痛点**

- 视频课程单向，学生无法互动
- 文档学习枯燥，缺乏引导和节奏感
- 制作高质量互动课程成本极高

**解法**：用户输入一个主题 → 系统生成一堂由 AI 老师与 AI 同学共同参与的沉浸式互动课程。

---

## 2. 目标用户

| 角色 | 核心场景 |
|---|---|
| 企业培训负责人 | 输入「新员工信息安全培训」，快速得到可播放课程 |
| 学习者 | 进入课堂看 AI 老师讲课、AI 同学提问，随时互动 |
| 课程开发者 | 对生成课程二次编辑：调大纲、换角色、改台词 |
| 管理员 | 查看学习记录、测验成绩、课堂时长 |

---

## 3. 核心用户流程

```
[首页输入主题]
    │
    ├──(并行)── [加载角色] / [加载用户素材]
    ▼
[确认角色] ── 用户点「继续」
    ▼
[生成大纲] ── outline_agent
    ▼
[生成场景内容] ── scene_agent（并行）
    ▼
[生成教学动作] ── action_agent（并行）
    │
    ├──(首个 Scene 就绪即跳转)──► [进入课堂]
    │                                  │
    └──(剩余 Scene 后台推流)────────► [播放引擎]
```

### MVP 完成标准（唯一）

```
打开产品 → 输入教学主题 → 配置模型 → 生成课程
→ Outline Agent → Scene Agent → Action Agent
→ Scene 1 Ready → 进入 Classroom
→ 教师讲解 → Slide → 字幕 → 播放 → 暂停 → 继续 → Scene 切换
→ 后续 Scene 动态进入 → 课程结束 → 保存 → 重新打开 → Replay
```

**链路中任何核心步骤是假实现，则不得宣称 MVP 完成。**

---

## 4. 页面清单

1. 首页 — 聊天式输入框 + 设置入口
2. 角色确认页 — 展示 5 位 AI 角色（1 老师 + 4 学生）
3. 大纲生成页 — 生成进度 + agent trace
4. 教学动作生成页 — action 编排进度
5. 课堂主界面 — 左 Scene 列表 / 中 Slide + 字幕 / 右笔记对话 / 底部控制条
6. 角色介绍浮层 — 点击头像查看角色详情

---

## 5. 非功能需求

| 维度 | 要求 |
|---|---|
| 性能 | 首页 TTI < 2s；切场景 < 300ms |
| 可用性 | 生成失败必须能回到上一步而不丢输入 |
| 安全 | API Key 存 Dexie（IndexedDB），不硬编码、不进 Git、不进日志 |
| 可观测 | 每次 LLM 调用有 trace（model / tokens / latency / cost） |
| 可测试 | 核心逻辑（播放引擎、数据转换）必须有单测 |

---

## 6. 反目标（明确不做）

社交、商城、直播、支付、复杂后台、企业权限、复杂 CRM。

Phase 4 的云同步/账号/团队/协作/分析/权限**不得阻塞 Phase 1**。

---

## 7. UI 原则

专业、现代、沉浸式、课堂感、清晰、低认知负担。

**但 UI 永远不能优先于真实功能。** 顺序：功能正确 → 数据正确 → Runtime 正确 → Agent 正确 → 视觉优化。
